[BatchLLM](https://arxiv.org/html/2412.03594v2#S4.SS2) groups requests by a single shared prefix to simplify KV-cache reuse during batching. Algorithm 1 reorganizes a compact prefix tree so more of the shared tokens are available in those first-level groups.

### 1. The tree structure and the meaning of “prefixes”

A node stores a segment of consecutive tokens. The path from the root to the node represents a full prefix. In a proper prefix tree, children at a branch already differ at the first token after the shared prefix. The reuse comes from multiple prompts passing through the same segment, so its KV states can be computed once for the group.

### 2. The recursive structure (optimal substructure)

```
function MaximizeReuse(D)
  if D has no children then
    return
```

- **Base case**: A leaf node has no children, hence no first-level prefixes to reuse.  
- **Inductive step**: The refactoring at `D` is computed *after* its children have been processed (hence the recursive call).

---

### 3. Bottom-up processing order

```
  for child ∈ D.children do
    MaximizeReuse(child)   // Solve sub-problems
```

- This is **post-order traversal**: children are solved first, then their parent.  
- The recursive call reorganizes the child subtree before its parent considers further merges.

---

### 4. The local decision at node `D`

For every grand-child `gchild` of `D` (i.e., a child of a child):

```
  gain ← (leaves(gchild) - 1) × tokens(gchild)
  penalty ← tokens(child)
```

- **Gain** estimates how many *tokens* we *save* if we reuse `gchild`’s token sequence:  
  – `leaves(gchild)` is the number of leaf nodes (final completions) that pass through `gchild`;  
  – `(leaves(gchild) - 1)` is the number of *extra* times we can reuse the same token sequence;  
  – `tokens(gchild)` is the length (in tokens) of that sequence.  
  Multiplying them gives total saved tokens.

- **Penalty** is the cost of creating the *fork* (duplicating the child’s prefix).

```
  if gain > penalty then
      Fork child and merge with gchild
```

- The paper applies this merge when the estimated saved tokens exceed the duplication cost. A positive local gain alone does not prove global optimality for arbitrary prefix-sharing objectives.

---

### 5. Traversal and implementation costs

The pseudocode uses post-order recursion and mutates the tree. It does not show a memoization table. On a fixed tree with $n$ nodes, the number of parent-to-grandchild checks is at most $n-1$ because each node has at most one grandparent. The total cost also depends on the calculation of leaf counts and the copying and merging of token segments. A bound for the static traversal alone therefore does not establish a runtime bound for the complete implementation.
